# CAOS

Лабораторная работа №1 по дисциплине «Архитектура компьютера и операционные системы».

Если папка с логами заполнена больше чем на X %, скрипт архивирует N самых старых файлов
(по дате изменения) в `backup` и удаляет их из папки. N выбирается минимальным, чтобы заполнение
стало не больше X %.

«Заполнение папки» — это заполнение файловой системы, на которой она лежит (`df`). Её размер и есть
лимит папки: скрипт печатает его строкой `Folder limit` и предупреждает, если папка лежит на общем
системном диске, а не на отдельном разделе.

Подробный разбор кода: [EXPLANATION.md](EXPLANATION.md).

## Linux (Ubuntu)

```bash
./linux/archive_logs.sh <папка_с_логами> [порог_%=70] [папка_для_архивов=<родитель>/backup]
```

```bash
LAB1_MAX_COMPRESSION=1 ./linux/archive_logs.sh /mnt/lab/log 70
```

- Порог — целое число от 0 до 100, по умолчанию 70.
- `LAB1_MAX_COMPRESSION=1` — сжатие lzma (`.tar.lzma`) вместо gzip (`.tar.gz`).
- Коды выхода: `0` — всё хорошо, `1` — ошибка, `2` — порог недостижим (место занято чем-то вне папки).

Тесты:

```bash
./linux/test_archive_logs.sh
```

Тесты создают виртуальный диск на 1 ГБ (tmpfs через `sudo mount`, поэтому один раз спросят пароль)
и прогоняют 5 сценариев. В каждом папка с логами весит больше 0,5 ГБ. Результат каждого теста —
`true` или `false`. После тестов всё удаляется.

## Windows

```bat
windows\archive_logs.bat <папка_с_логами> [порог_%=70] [папка_для_архивов]
```

```bat
set LAB1_MAX_COMPRESSION=1
windows\archive_logs.bat D:\log 70
```

Тесты — те же 5 сценариев. Запускать в командной строке **от имени администратора**: виртуальный диск
(VHD на 1 ГБ) создаётся через `diskpart`.

```bat
windows\test_archive_logs.bat
```

Используется встроенный `tar.exe` (Windows 10 1803+). Файлы `.bat` должны храниться с окончаниями строк
Windows (CRLF), за это отвечает `.gitattributes`.
